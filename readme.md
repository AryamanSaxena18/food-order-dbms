# Food Order Management System - DBMS Project

A relational database project for managing and analyzing food orders. The project demonstrates practical DBMS concepts including database design, normalization, SQL queries, views, indexes, stored procedures, functions, triggers, transactions, concurrency concepts, and query optimization.

# Database Design

The database is organized into separate entities to reduce data redundancy and improve data integrity.

## Main Tables

- `customers` — stores customer information
- `restaurants` — stores restaurant information
- `cuisines` — stores available cuisine types
- `restaurant_cuisine` — maps restaurants to cuisines
- `orders` — stores individual food orders
- `stg_food_order` — staging table containing the original dataset
- `order_audit` — stores audit information generated by triggers

## Relationships

```text
Customers
    |
    | 1 : N
    v
 Orders
    ^
    | N : 1
Restaurants
    |
    | M : N
    v
Cuisines
```

Primary keys and foreign keys are used to maintain referential integrity between related tables.

# Example Query

Find the average order cost for each cuisine:

```sql
SELECT
    c.cuisine_name,
    AVG(o.cost_of_order) AS average_order_cost
FROM orders o
JOIN cuisines c
    ON o.cuisine_id = c.cuisine_id
GROUP BY c.cuisine_name
ORDER BY average_order_cost DESC;
```

# Normalization Approach

The original CSV contains repeated information such as restaurant names and cuisine types.

For example:

```text
Order 1 → Hangawi → Korean
Order 2 → Hangawi → Korean
Order 3 → Shake Shack → American
```

Instead of storing these values repeatedly, the project separates them into dedicated tables.

```text
                 +--------------+
                 |  Customers   |
                 +------+-------+
                        |
                        v
                 +--------------+
                 |    Orders    |
                 +------+-------+
                        |
                        v
                 +--------------+
                 | Restaurants  |
                 +------+-------+
                        |
                        v
                 +--------------+
                 |   Cuisines   |
                 +--------------+
```

This helps reduce redundancy and improves data consistency.
